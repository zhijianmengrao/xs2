## 2. 为什么是这一轮

R133 的 N2 只钉「索引链接集合 == 磁盘集合」，R137 的 S 系只钉 §1 三行；
§4 的日期与主题一直手抄。R144 §7 登记时实测 118 行 0 日期漂移、7 处主题
差——**0 漂移不是判据的功劳，只是还没抄错**；主题差则是「同一件事两种
写法」，读者要在表与标题之间脑内归一。

L5/L6 的锚点选在「文档一旦存在就只有一个答案」的字面上：

- 日期：`git log --diff-filter=A` 的首次入库提交，文档提交后唯一；
- 主题：H1 副标题（N3 已钉标题形状），归一后唯一。

L7 是两条判据的语料守卫：行被删、链接错位、日期非法时，L5/L6 可能
静默少判一行而不自知。

## 3. 实现

### 3.1 `tests/test_index_row_self_description.py`（L5–L7）

| 判据 | 内容 | 锚点 |
|---|---|---|
| L5 | §4 每行日期 == 该文档首次入库提交日期（`--diff-filter=A`，取最早一条） | git 提交日期 |
| L6 | §4 每行主题 == H1 副标题（NFKC + 去空白/标点/反引号/强调符后逐字相等） | H1 副标题 |
| L7 | §4 行集合 == 磁盘交接文档集合；行首轮次 == 链接目标；日期是合法 ISO 日期；主题非空 | 表的行形状 |

实现要点：

- **latest 豁免只在「git 里取不到首次入库日期」时生效**：本地提交前跑
  全量，本轮文档还是 untracked；一旦提交（CI 的检出树），latest 也照判。
  取不到日期且不是 latest → 红（浅检出纪律，R136）。
- 归一不是放宽内容：数字与汉字都保留，只有括号、冒号、间隔号、反引号
  不参与对账。R117 的「（fetch-chain）」vs「· fetch-chain」、R132 的
  `` `assert` `` vs `assert` 都因此可解析。
- L7 与 N2 互补：N2 判链接集合，L7 判行能解析且自述完整——行写坏但
  链接还在时，N2 可能仍绿。
