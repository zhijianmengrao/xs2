「第二份账」病有三处病灶：文档不回改（§6.2）、索引覆盖靠人记（R133 已

## 3. 实现

### 3.1 `tests/test_index_snapshot.py`

- **S1 交接文档行**：`**N 份**` 的 N == `docs/HANDOVER_ROUND*.md` 数量；
  行内 `HANDOVER_ROUND24..M.md` 区间两端 == 磁盘最小/最大轮次号——份对
  区间错也红。
- **S2 写回行**：`**K / 80 轮**` 的 K == history.json 条数，行内末条
  `ci-<id>` == 第 K 条的 run_id（行内自洽 + 磁盘恰等双重）。
- **S3 用例行**：数字 == `pytest --collect-only -q` 的收集数（subprocess，
  300s 超时；收集失败原样带出）。**不钉**括号里的 passed/skipped（平台
  差异）与「预计」注记（预期值）。
- 行**存在性**由 `_index_row` 的显式 AssertionError 担保：行被删即红。

### 3.2 与 bot 提交竞态的口径

backend job 在自己的提交树上跑测试，写回 bot 提交是另一棵树——测试
看到的 history.json 恒等于提交时的磁盘，**严格恰等成立**（R136 §7 预告
的竞态在实测中不存在：bot 提交不会改已检出的树）。

### 3.3 刻意不做的

- 不钉「CI 闸门 10 job」行（R135 的矩阵展开判据已机判同一口径）；
- 不把「预计 n+1」注记机械化（预期值不是实况）。
