## 1. 本轮最重要的一件事：字面照抄 R63 的 c_max 修不掉那次红

R64 §11 把两个预算算出来了：共模 0.400s、单段只拖前一段时 **0.133s**。于是
「把预算改成逐段的」有一个看起来最省事的落法：每段各自判
`|实测 − 配置| ≤ 0.133s`。

**这条路修不掉 R64 那次红。** 那次首段偏移是 **0.16s** > 0.133s，改完之后照样
红，只是报错从「第 1→2 段未递增」变成「第 1 段超睡 0.16s」。它换的是**归属**，
不是**红绿**。

要让 CI 不再偶发红，容差必须大于实测抖动；而这件事有一个比「拍个更松的数」
更硬的依据（§2）。真正落地的是：欠睡 0.05s / 超睡 0.30s，且**容许的超睡上限
必须严格小于相邻配置差**（0.4s），否则「下标错一位」这种回归会掉进容差。

## 2. 第二件事：容差该不对称，依据是「开销不可能为负」

量的是请求到达间隔，它等于**配置的睡眠 + 开销**（JIT 预热、日志、调度、
事件循环）。开销不可能为负——除了计时器精度与四舍五入，没有机制能让一段
`sleep(0.4)` 变成 0.39。于是两侧的语义完全不同：

| 侧 | 判定 | 含义 | 容差 | 依据 |
|---|---|---|---|---|
| 欠睡 | `实测 < 配置 − 0.05` | 延迟没被等过 / 用了更小的一项 | **0.05s** | 计时器精度与三位小数量化 |
| 超睡 | `实测 > 配置 + 0.30` | 等得比配置长太多 | **0.30s** | 实测最坏抖动 0.16s 的 **1.9 倍** |

0.30s 不是随手拍的：它必须同时满足两条——
1. **大于实测最坏抖动**：R64 §11 的 0.16s，余量 1.9 倍；
2. **小于相邻配置的最小差**：本项目三个形状场景都是 0.4s，所以 0.30s 取在
   「严格小于 0.4」一侧（取 0.40 就与 0.4s 的配置差重合，等于允许「下标错一位」
   通过）。

这条约束被写成代码：`RisingShapeSegmentBudget.judgeable = 0 < over_tol < min_gap`。
降到 0.2 起时 `min_gap = 0.2 < 0.30` → 判 False，`_shape_headroom_note` 会
逐字写出「分不出『用错相邻一项』」而不是默默判合格（R62 的同一条纪律）。

## 3. 第三件事：换判据顺带补上旧判据的一个盲区

比值判据对「每段都按比例放大」是结构性失明的：`[0.8, 1.6]` 对配置 `[0.4, 0.8]`
的比值仍是 2.0/2.0，全绿。逐段判在每段都多出 0.4/0.8 时全红。

这不是假想的形状（把 delays 当「倍数」用、或配置里混进两次缩放），而且它比旧
判据**更严重**才被发现：旧判据在「统一 ×2」时唯一能依靠的是单点幅度场景
（`retry_backoff_is_honoured`，配 1.2s 判多出 ≥0.7s），那个场景只看一个值。

## 4. 设计

1. `_rising_shape_violations` 改为**逐段**判：`zip(segments, configured)`，
   每段算 `deviation = measured − configured`，两侧按 §2 的容差各判一次。
   段数不足仍报「只量到 N 个」而不是默默通过（R53 的「永远绿的防护」入口）。
2. **比值降为诊断行**：`_shape_headroom_note` 的末尾仍打印
   「参考：相邻比值 [...]（诊断用，不参与判定）」。理由：它是解释「为什么这一段
   慢」的最短线索，但它不再决定红绿——一条判据只能有一个判决口径（R55 教训：
   两套式子迟早对同一个量给出两个答案）。
3. `RisingShapeOffsetBudget` → `RisingShapeSegmentBudget`：`worst_pair` /
   `offset_budget` 换成 `under_tol` / `over_tol` / `min_gap`。**中位数换成最大值**：
   判据是最坏情况判据，余量也必须按最坏段报。R64 那次只记到前两段
   （0.56 / 0.81，偏差 `[+0.16, +0.01]`）；三段情形下中位数会把首段那 0.16
   稀释掉（构造例 `[0.56, 0.81, 1.62]` 的偏差 `[+0.16, +0.01, +0.02]`，中位数
   只有 0.02），而判决是被 0.16 那一段推翻的。
4. 三个形状场景的 `delays` 不变（0.4 起）；docstring 里「因为比值门槛的偏移
   敏感性所以不降到 0.2 起」换成「因为 `min_gap` 必须大于超睡容差所以不降到
   0.2 起」——结论相同，理由换成了判据自己的算术。
