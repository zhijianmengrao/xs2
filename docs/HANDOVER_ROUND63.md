# DeterminFlow (xs2) 交接报告 — Round 63（min_ratio 判别力边界：失明点是 c==a，实测余量 25–67 倍）

> 本轮定位：R53 §11-2 / R55 §11-2 挂账两轮的「`min_ratio=1.5` 适用量级有限」。
> 基线：`f084f5e`（R62 收尾：Low 2127/113/0、High 2212/28/0（权威）、
> 总用例 2240、前端 490/0）。落地形态由用户拍定三项：**主线 = min_ratio
> 判别力精确定量**；**范围 = 只做主线收口**；**收尾 = 照常推送 + 五 job 逐字核对**。

## 1. 本轮最重要的一件事：边界从「定性说法」变成「可复算的式子」

R53 只钉了两个点（0.4→0.8 配 0.15s 偏移合格、0.1→0.2 不合格），R55 记的是
「当前只有一条测试钉住这两个点，没有给出『什么量级下这个门槛开始不可信』的
公式」。本轮把它算出来：

```
实测比值 (b + c) / (a + c) >= min_ratio
等价于  真实比值 rho >= min_ratio + (min_ratio - 1) * (c / a)      # c = 共模偏移，a = 首段配置
```

对 2 倍递增、门槛 1.5：**失明点正好是 `c == a`**。偏移与首段等长时，
真实的翻倍与恒定额给出同一个比值 1.0——判据在这一侧结构性看不见。

两个被钉住的点都是这条式子的特例：`c/a = 0.375` 时要求 `rho >= 1.6875`
（实际 2，合格）；`c/a = 1.5` 时要求 `rho >= 2.25`（实际 2，不合格）。
这不是拟合，是解不等式。

## 2. 另一端：`floor` 过滤把 0.1 量级的窗口压成单点

`_backoff_segments(floor=0.2)` 会把 0.2s 以下的间隔当非退避丢掉，所以首段还必须
满足 `a + c >= floor`。两端取交集：

| 配置首段 | 比值门槛给出的上界 | floor 给出的下界 | 可判窗口 |
|---|---|---|---|
| 0.4 | 0.40s | 0s | `[0, 0.40]` |
| 0.2 | 0.20s | 0s | `[0, 0.20]` |
| 0.1 | 0.10s | 0.10s | **`[0.10, 0.10]` 单点** |

这就是 R53 用 0.1→0.2 举例会被判红的算术原因：那个量级上不存在「有宽度」的
可判区间。`judgeable` 用严格大于判窗口宽度，单点即不可判。

## 3. 实测偏移：R53 的 0.15s 假设是真实值的 8–25 倍

三批实测（同一场景、不同机器/runner）：

| 来源 | 配置 [0.4, 0.8, 1.6] 实测 | 逐段偏移 | 中位数 | 余量 |
|---|---|---|---|---|
| 本机（首次） | `[0.416, 0.818, 1.614]` | +0.016 / +0.018 / +0.014 | 0.016s | 25 倍 |
| 本机（全量 e2e） | `[0.409, 0.805, 1.609]` | +0.009 / +0.005 / +0.009 | 0.009s | 44 倍 |
| CI ubuntu | `[0.406, 0.808, 1.608]` | +0.006 / +0.008 / +0.008 | 0.008s | 50 倍 |

四段场景同量级（本机 +0.009…+0.019、CI +0.006…+0.007），两段场景 CI 是
0.007s（57 倍）、四段 CI 是 0.006s（67 倍）。

**两条必须一起读的限定**：

1. 这些是**点估计**，不是分布。中位数在 2–4 个段上很粗；一次被调度拖慢半秒的
   运行不会改变中位数，但会改变那一次的实际比值。
2. 模型是**加性共模偏移**（判据 docstring 一直用的那个模型）。真实的抖动还含
   乘性成分与单段离群，式子只回答「按这个模型，多远开始失明」。

结论不是「判据很安全」，而是：**R53 写下的 0.15s 从未被观测到；真实偏移比它小
一个数量级，离 0.40s 的预算还有 25–67 倍。**

## 4. 设计：三个函数 + 输出自带余量

1. `RisingShapeOffsetBudget`（frozen dataclass）：`worst_pair` / `offset_budget` /
   `floor_offset`，`judgeable` 用严格大于判窗口宽度。
2. `_rising_shape_offset_budget(configured, min_ratio=1.5, floor=0.2)`：逐对求
   `c_max = (b - r*a) / (r - 1)` 取**最紧**的一对；负预算是合法返回值——它说明
   配置本身达不到门槛（`[0.4, 0.5]` 比 1.25 < 1.5），零偏移也判不过，属配置
   写错而不是判据太松。单段配置与 `min_ratio <= 1` 抛 `ValueError`。
3. `_measured_common_mode_offset(segments, configured)`：**中位数**而非均值。
   单段被拖慢时均值会被拽走（测试里用 `[2.0, 0.82, 1.61]` 钉住：中位数 0.02，
   均值 0.54）。
4. `_shape_headroom_note(...)`：三个形状场景的 PASS 详情改带预算与实测，例如
   `实测 [0.406, 0.808, 1.608]；偏移预算 0.40s/段，实测偏移 0.008s（余量 50 倍）`。
   判不了时（单点窗口 / 配置达不到门槛 / 没量到段）各写各的话，不冒充合格。

**这就是 R62「判据说不出话时必须写进输出」的镜像**：说得出话的判据，应该把
自己的余量也写出来——只说「符合配置」的日志无法区分「离边界很远」与「擦着
门槛过关」。
