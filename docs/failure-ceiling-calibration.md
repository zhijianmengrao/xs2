# 失败率政策上限校准（R61，2026-10-30）

> 校准对象：`scripts/check_live_snapshot_gate.py --fail-if-above 8` —— CI 里
> 真实快照主闸门的政策上限。
> 判据算术：95% Clopper-Pearson 单侧界 + 三分法（下界 > 上限才 `exceeds`，
> 上界 ≤ 上限才 `normal`，横跨则 `undetermined`）。
> 本文所有数字都由闸门自己的 `_cp_interval` / `_ceiling_verdict` 算出，没有
> 第二份公式；复现命令见 §9。

## 1. 结论

**维持 8%。** 它不是随便拍的，也不是最优之外的可选项：

1. **8% ≈ 全历史样本失败率上界的整数化**：本机 `data/workflows` 全部 40 个 run
   合计 16/297 = 5.39%，95% 上界 **8.07%**。8% 落在这条上界上（差 0.07 个
   百分点）。
2. **低于 8% 的整数值在当前样本量下不可用**：上限 ≤ 6.56%（当前快照 95%
   上界）时，当前数据立刻从 `normal` 变 `undetermined`——闸门再也说不出
   「正常」；7% 时政策带与回归带**完全重合**（见 §4），政策层不再有独立判决。
3. **高于 8% 只会更钝**：9% 时 10% 真实失败率的检出率从 26.0% 掉到 10.8%，
   10% 时掉到 3.4%。

同时必须记住它的三条已知代价（§5）：**它是突破线，不是健康线；不是漂移
探测器；样本量不够时它连「正常」都说不出口。**

## 2. 当前数据

| 项 | 值 |
|---|---|
| 入库快照 | 28 个 run / 9 个 workflow / **255 次尝试 / 10 失败 = 3.92%** |
| 95% 精确界 | **[2.14%, 6.56%]**，半宽 2.64pp |
| 本机全部 run（40 个） | **16/297 = 5.39%**，95% **[3.41%, 8.07%]** |
| 快照取的是哪一批 | `--limit 5` 窗口内的 28 个 run（40 个里较旧的 12 个不在快照里） |

**run 级失败率不能用来校准**：40 个 run 里 26 个零失败，6 个是 `1/1 = 100%`
的单节点 run，p50 = 0%、p90 = 100%。run 之间的尝试数从 1 到 30（中位 5）不等，
逐 run 的百分比度量的是 run 的长度而不是稳定性。校准必须在**尝试**这一层做。

## 3. n=255 时 8% 上限的实际判决带

| 判决 | 失败次数 k | 观测失败率 | 含义 |
|---|---|---|---|
| `normal` | **k ≤ 13** | **≤ 5.10%** | 有证据表明不高于 8% |
| `undetermined` | 14 ≤ k ≤ 28 | 5.49% – 10.98% | 样本不足以判 |
| `exceeds` | **k ≥ 29** | **≥ 11.37%** | 有证据表明高于 8% |

这就是「8% 不是健康线」的准确含义：**判 `normal` 的实际门槛是 5.10%，不是
8%。** 8% 是 `exceeds` 那一侧的命题，而它需要观测值比自己还高才能开口。

## 4. 候选上限对比（n=255，同一份当前数据）

| 上限 | normal 到 | exceeds 从 | 10% 真实率的检出率 | 12% 真实率的检出率 | 50% 功效对应真实率 | 当前数据判决 |
|---|---|---|---|---|---|---|
| 6.00% | 3.14% | 9.02% | 72.9% | 94.5% | 8.90% | **undetermined** |
| 6.50% | 3.53% | 9.41% | 65.3% | 91.8% | 9.30% | **undetermined** |
| 6.92%（= 回归阈值） | 3.92% | 10.20% | 48.9% | 83.7% | 10.10% | normal |
| 7.00% | 3.92% | 10.20% | 48.9% | 83.7% | 10.10% | normal |
| **8.00%** | **5.10%** | **11.37%** | **26.0%** | **65.0%** | **11.25%** | **normal** |
| 9.00% | 5.88% | 12.55% | 10.8% | 42.2% | 12.45% | normal |
| 10.00% | 6.67% | 13.73% | 3.4% | 22.3% | 13.60% | normal |
| 12.00% | 8.24% | 15.69% | 0.3% | 4.7% | 15.55% | normal |

三条读法：

- **6.00% / 6.50% 不可用**：normal 带上界低于当前点估计 3.92%，当前数据自己
  就判不了。上限不能低于快照的 95% 上界（6.56%），这是样本量给的硬下限。
- **7.00% 与回归阈值 6.92% 的判决带逐 k 相同**（normal ≤ 10、exceeds ≥ 26）：
  政策层与回归层在 n=255 下是同一个台阶，多一层没有增加任何判决力。8% 是
  **第一个**让政策层有独立判决带的整数（且与回归层隔 3 次失败：26 vs 29）。
- **8% 同时是可用区间里最敏感的值**：再往上 9%/10% 的检出率掉一个量级。

## 5. 三条已知代价（校准的负结果，必须一起读）

1. **真实失败率恰为 8% 时，闸门几乎永远说不出「正常」**：P(normal)=4.9%，
   P(undetermined)=91.5%，P(exceeds)=3.6%。这不是缺陷：点估计落在上限上时
   上界必然高于上限，任何样本量都如此。所以 8% 只能当**突破线**用。
2. **它不是漂移探测器**：真实失败率翻倍到 7.84%（2× 基线）时检出率只有
   **2.85%**；50% 检出要真实值到 **11.25%**，80% 到 **12.96%**，95% 到
   **14.75%**。2%→7% 这种回归由 `--fail-on-regression` 负责，不是上限。
3. **精度受样本量限制**：想让「normal」覆盖到 6% 的观测值，需要约 **475 次
   尝试**（当前 255）；想让 10% 真实率有 80% 检出率，需要约 **1221 次尝试**
   （精确界实算：n=600 → 52.0%、n=800 → 61.0%、n=1000 → 71.6%）。当前样本下
   它判的是「有证据表明突破 8%」，不是「有没有变化」。

误报侧由构造保证：真实率 3.92% 时 P(exceeds)=0.0000；按全历史 5.39% 算
P(exceeds)=0.014%。上限不会因为重导噪声变红。

## 6. 与回归层的排序（两层结构的可用性）

| 层 | 阈值 | n=255 时先红于 |
|---|---|---|
| 回归（基线 3.92 + 余量 3） | 6.92% | k ≥ 26（10.20%） |
| 政策上限 | 8.00% | k ≥ 29（11.37%） |

间隔 3 次失败（1.17 个百分点）。上限若压到 7% 及以下，这个间隔归零，回归层
「先于上限开口」的性质消失（配置层会打印恒绿告警）。8% 保住了它。

## 7. 实现边界（顺带挖到的，不是本轮要修的）

`_binomial_cdf_le` 用 `math.comb` 精确求和，`math.comb(n, k)` 超过 float 上限
（约 1.8e308）时抛 `OverflowError`。实测边界取决于**形状**而不只是 n：

| 形状 | 结果 |
|---|---|
| n=1100, k=550（50% 失败率） | **OverflowError** |
| n=255, k=10（当前数据） | ok |
| n=4000, k=160（4% 形状，模拟样本长 15 倍） | ok（区间 [3.50%, 4.55%]） |

结论：本项目的失败率形状（约 4%~10%，即 k ≪ n）在本机数据长到 4000 次尝试
之前都不会碰到这个边界；只有「失败率接近 50%」的极端形状会在 n≈1100 处炸。
届时是**响亮的崩溃**（traceback，非静默放行），不是恒绿。若样本量将来真涨到
那个量级，改法是把二项分布改到对数空间算——记为独立的技术债，不在本轮。

## 8. 未校准的部分

- **per-workflow 没有绝对上限**：各 workflow 的合理失败率不同，不发明政策值
  （R58 结论不变）。per-workflow 层仍是「留一法基线 + 余量」。
- **8% 本身是政策判断**：数据能证明的是「8% 与观测过程的上界一致、且是可用
  区间里最敏感的整数」；「8% 这个失败率是否可以接受」是业务判断，不是本校准
  能回答的。若政策改为 6%（例如产品要求更严），当前样本量必须同步涨到约 475
  次尝试，否则闸门会退化成永远 `undetermined`。
- **失败率的成因未分层**：255 次尝试里 10 次失败集中于 build(3)、mvp(4)、
  character(2)、post-hoc(1)。上限判总量，成因分析属
  `scripts/provider_failure_profile.py` 与趋势面。

## 9. 复现

在仓库根执行（只用闸门自己的算术）：

```bash
# 当前快照区间
python -c "import sys; sys.path.insert(0,'scripts'); import check_live_snapshot_gate as g; print(g._cp_interval(255,10))"
# 8% 上限下 k=29 的判决（应 exceeds）、k=28（应 undetermined）、k=13（应 normal）
python -c "import sys; sys.path.insert(0,'scripts'); import check_live_snapshot_gate as g; print([g._ceiling_verdict(255,k,8.0)[0] for k in (13,28,29)])"
# 真实失败率 10% 时的检出率
python -c "import sys; sys.path.insert(0,'scripts'); import check_live_snapshot_gate as g; print(1-g._binomial_cdf_le(255,28,0.10))"
# 全历史样本（40 个 run）的合计口径
python -c "import sys; sys.path.insert(0,'scripts'); from pathlib import Path; import check_live_snapshot_gate as g; a,f=g.recompute_totals(Path('data/workflows')); print(f,a,g._cp_interval(a,f))"
```

`data` 目录不在 CI 检出里，最后一条只在本机可跑；CI 里的权威数字是快照的
255/10。

## 10. 与 CI 的关系

CI 不需要任何改动：上限仍是 8%，反向验证仍是 1%。本校准的产出是**把 8% 的
依据与代价写成可复核的记录**，并把「政策带 actual 边界（5.10% / 11.37%）」
写进闸门脚本与 CI 的注释——读代码的人不必再猜 8% 是从哪来的。
