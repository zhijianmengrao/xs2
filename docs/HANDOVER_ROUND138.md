## 1. 一句话结论

- **实测缺口**：`scripts/verify_release.py` 自 R132 起有 0/1/2/4 四类互不
  冒充的退出码，但 ``docs/RELEASE_SOP.md`` §5（发版人的操作手册）**一句
  退出码都没教**——非 0 退出时操作者分不清「判了不合格（停发）」和
  「环境问题（修了重跑）」。且 SOP 不在 R133 三份活文档清单里，它的
  引用面无人守。
- **SOP §5 新增退出码判决表**：0=`ALL CHECKS PASSED` 可发版；1=`[fail]`
  判了不合格停发；2=`[error]` 环境未判定；4=`[shape]` 形状未判定——
  各行带处置动作。
- 新增 `tests/test_release_sop_contract.py`（3 函数 / 3 条）：
  **T1** SOP 表代码集合 == 脚本 `EXIT_*` 常量集合，行内输出标记
  （`[fail]`/`[error]`/`[shape]`/`ALL CHECKS PASSED`）必须是脚本真实
  字面前缀；**T2** SOP 引用的 `scripts/*.py` 全部在库；**T3** §5 验收
  命令保留 `--tag`/`--assets-dir`（R32 参数化接口）。
- 变异 **M1–M4 4/4** 咬合：表代码 1→3（2 红）、脚本常量 4→5（2 红）、
  输出标记改坏（2 红）、`--assets-dir` 改名（1 红）；还原 sha256 一致。

## 2. 为什么是这一轮

R132 的判据把「判决」从 `assert` 变成了显式退出码，但判决的**消费者**
是看 SOP 发版的人——手册没教退出码，判决分类就只活在代码里。五轮连推
（五）的自描述纪律到第 4 轮：工具的行为（R132）、闸门的清单（R135）、
账本的账（R136）、索引的数（R137），最后是**手册与工具的同账**（本轮）。
SOP 引用面也补进导航层判据家族（T2）。

## 3. 实现

### 3.1 SOP §5 退出码判决表

- 四行表：代码 / 脚本输出字面前缀 / 含义 / 处置；注记

### 3.2 `tests/test_release_sop_contract.py`

- **T1**：双向同账——SOP 表缺代码、多代码、常量改值、输出标记漂移
  （`[fail]`→`[failx]`）都红；脚本里三个 `[...]` 前缀被改名也红。
- **T2**：`scripts/<name>.py` 引用可解析（当前 `verify_release.py`）。

  （首版误抓节标题行——命令行锚定改为代码围栏内查找，见 §5 教训）。

  细则台账 §10.12 与 test_verify_release 担保）；
- 不把 verify_release 接进 CI（R132 已论证：缺发行产物只会永远退 2）。
