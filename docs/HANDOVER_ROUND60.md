## 1. 本轮最重要的一件事：判据上线了，但这次是「自比自」

`--limit 5` 重导后 `history` 从 1 轮变 2 轮，回归判据第一次在真实快照上判出了结论：

```
[历史基线回归] 基线取自历史上一轮（9 个 workflow，10/255）；失败率 3.92%
（n=255, 失败 10），95% 区间 [2.14%, 6.56%]，基线 3.92% + 余量 3 = 阈值
6.92%：整个区间都在阈值之内，判没有回归。退出码 1 的来源：无（已启用的判据都没有判失败）
```

必须同时说清它证明了什么、没证明什么：

- **证明了**：基线选取（`history[-2]`）、workflow 集合比对、Clopper-Pearson 区间、
  超限判定与「退出码 1 的来源」行，在真实数据上全部走通。CI 里这一步从此不再是
  「判不了回归」的占位输出。
- **没证明**：质量在时间上稳定。**两轮是同一批 run**——本机 `data/workflows`
  最新的 run 停在 2026-10-26/27，2026-10-29 那次导出之后没有新 run，`--limit 5`
  再次选中的仍是同一批 **28 个 run**，计数逐字段相同（255 次尝试 / 10 失败 /
  3.92%）。所以第二条 history 是第一轮的**完全副本**，只有 `exported_at` 不同
  （`2026-10-29T01:28:46Z` → `2026-10-30T09:26:54Z`）。

这是 R59 §9-2「相邻两轮可能重叠」的极端值：重叠 100%。方向仍然是保守的——重叠
让区间偏宽、偏向「判不出」，不会误报回归；但读日志的人必须知道，这一轮写下的
「没有回归」是**机制验证**，不是质量结论。真实的时间序列比较要等下一次**有新 run**
的导出：那时 baseline 才是另一批样本。

顺带记一条状态：`undetermined_streaks` 的「连续 3 轮样本不足」提示要第 3 轮起
才可能生效，现在 history 是 2 轮，该提示仍未启用。

## 5. 为什么这一轮没有新测试

数据轮没有新行为可钉：判据的行为 R59 已有 120 条测试覆盖（基线选取、薄基线、
集合变化、双来源、`history` 封顶、坏条目跳过等），重导只改变量的**取值**，不改
代码路径。新增测试只会把「10/255」这个数字再抄一遍；而给入库真实快照加数值断言，
会让下一次重导先红——R58/R59 定的纪律是「反向验证 fixture 的数字漂了测试先红」，
真实快照恰好相反，它本来就该随每次导出变化。

现有测试已足以守住本轮改动：`test_committed_snapshot_records_the_current_export_in_history`
要求 history 最后一条等于当前 `per_workflow`；`test_payload_scan_covers_every_snapshot_fixture`
与裁剪契约扫描覆盖所有 fixture；2106/2191 两条全量全绿已实证。
