# 剧情、人物与连续性接入说明

0.1.13 将三个项目中的具体代码和方法接入现有文件工作流。页面统一使用「创作助手」，开书顾问、剧情讨论、参数建议与返修仍共用 Core 的默认大模型。

## 来源和实际使用范围

| 项目 | 固定版本 | 原始文件与接入位置 |
|---|---|---|
| [novel-copilot](https://github.com/andy-develop/novel-copilot) | `9c0dec4ae031b92c827bbe2f1b994c67b700dde7` | `methods()` 运行时读取原版剧情发散、人物信念和声音文档；`rank()` 改编 `auto_write.py:cmd_score` 的加权评分，用于候选比较 |
| [ai-novel-assistant](https://github.com/furthermoreover/ai-novel-assistant) | `be9509ab024a722a3e5898395815bd0b5ad30d6d` | `upstream.py` 保留原版 `parse_markdown_chunks`；保留 `story_state_text` 的格式化主体，将数据库查询替换为输入本书的确认状态；两者由 `context()` 和 `methods()` 实际调用 |
| [novel-helper](https://github.com/XFSeven7/novel-helper) | `1f3913991c6e12e19b1b50f9d486a757c40b55c9` | 将 `outlineStageChat/patch.ts` 的围栏解析与归一化移植为 `parse_proposal()`；采用局部讨论和场景卡片字段；`methods()` 读取原版救场提示的事实和引用约束 |

`vendor/` 保存相关原始文件，`UPSTREAM.json` 记录版本与逐文件 SHA256。测试对所有留存文件重新计算哈希，验证来源，并实际执行复用函数。

没有启动这三个项目的独立服务。它们原有数据库、界面、自动应用整棵大纲的行为不属于本次接入范围。评分仍是模型提供分数后的加权比较，不是客观文学质量评测。固定爽点配额、无伏笔的新势力奖励、自动改写大纲树等做法没有沿用。

## 作者如何使用

1. 在当前作品点击「创作助手」，选择本章、当前卷或整书讨论。没有蒸馏资料也可以讨论原创故事。
2. 点击发展方向、检查动机或看点，或直接提出具体问题。回答会读取本书设定、采用写法、最近正文、确认人物状态及相同范围的历史讨论。
3. 有候选方案时，打开预览，阅读目标、阻力、人物选择、代价、期待兑现及原句依据，再明确采用。讨论本身不写入大纲。
4. 采用后按钮显示「已采用」；重复请求返回同一回执。既有手动大纲保留，修改前保存备份。已经写出的章节使用返修流程。
5. 章节生产、润色、读者评估和后验都读取共同上下文。采用方案会记录到本章 `planning_context.json`，用于核对实际调用。

## 连续性约定

- `story/<章>/planned_*.json` 是待写计划，不能作为正文事实或人物已知信息。
- `post-hoc` 在分析前记录正文和前文哈希，最后才提交 `confirmed_state.json`。人物、世界新增事实、伏笔和债务确认必须带正文中连续存在的原句。
- 未实际埋设的计划不进入正式伏笔账本；单纯提及不算回收。既有编号保留，关系有方向，不推定双方认识相同。
- 人物当前处境与长期动机分别保存。未变化的字段保留；作者规划的幕后演进与人物所知分开。
- 修改历史正文后，相关章及后续依赖章的确认快照失效。续写先审核过期档案，再核对大纲覆盖，不重跑开书顾问。
- 每章世界预测单独保存，历史审核不会误读其他章节的共享缓存。
- 一键返修复评通过后同步档案；未通过则展示问题并暂停。自动全流程按原有返修上限运行。

## 工程入口

| 入口 | 数据去向 | 验证证据 |
|---|---|---|
| Core `novel_assistant.py` | 持久助手历史、经过验证的候选 | Core `test_novel_story_assistant.py` |
| Core `/novel-console/plot/apply` | 原近纲的增量段、按章计划、备份、回执 | 显式采用、过期检查、正文保护测试 |
| 六个原工作流的 `script_story_context` | 同一个共同上下文及本章调用记录 | 工作流图连接测试与真实任务记录 |
| 后验 `script_confirm_archive` | 人物、世界、伏笔、债务和剧情变化档案 | 原句核验、历史返修失效、计划与事实分离测试 |
| `/continuation`、`/archive-state` | 可继续状态、有效动态档案 | 页面状态和 API 返回 |

在 Core 环境执行插件测试：设置 `PYTHONPATH` 为 Core 根目录，再运行 `python -m pytest <插件路径>/tests`。前端小说测试使用 `npx tsx --tsconfig tsconfig.app.json --test src/lib/novel-*.test.ts`。

这些约束能减少记忆断裂与过程记录式写法，但人物是否可信、兑现是否成立仍需要读者评估真实正文。
